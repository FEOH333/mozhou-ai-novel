# AI 小说写作工具 —— 完整技术方案

> 版本 v0.1（2026-08）｜ 形态：本地 Web 应用（Node.js 后端 + 浏览器 UI）｜ 零构建、零云依赖
> 核心模型：DeepSeek V4（`deepseek-v4-flash` 规划/审校/摘要，`deepseek-v4-pro` 正文，均可配置）
> 本地 embedding：transformers.js + bge-small-zh-v1.5（ONNX，约 100MB，首次运行自动下载）

---

## 1. 目标与设计原则

| 目标 | 手段 |
|---|---|
| 超长文本不跑偏 | 分层写作管线：设定→书纲→卷纲→章细纲→场景正文；每步独立请求、大纲锚定、要点覆盖校验 |
| 伏笔细节处理到位 | 结构化伏笔登记表（foreshadow ledger）：埋设→推进→回收全生命周期跟踪，写作指令强制注入活跃伏笔，审校环节检查遗忘 |
| 幻觉趋近于 0 | 事实库只存"已写文本抽取的事实"；正文指令注入相关事实并要求引用；章后抽取+冲突检测（superseded 机制）；生成后事实核查 |
| 紧跟大纲 | 细纲先行、人可编辑确认；正文指令携带本章细纲 + 覆盖校验（flash 检查要点是否落地） |
| 缓存命中率极高（DeepSeek 适配） | 稳定前缀 + 公共材料前置 + 按场景追加历史（append-only）+ 动态内容置尾；逐请求上报 `prompt_cache_hit_tokens` 监控 |
| 成本低 | 缓存命中价 0.02 元/M vs 未命中 1 元/M（差 50 倍）；flash/pro 任务路由；本地零成本检索；峰谷错峰提示；成本面板可视化"省了多少钱" |
| 使用方便 | 双击启动、浏览器即用；流程可人工干预（细纲确认、正文修订、审校放行）；无 npm 构建 |

### 1.1 零构建约束
- 后端：仅用 Node.js 内置模块（`node:http`、`node:sqlite`、`node:fs`、`node:crypto`、`node:path`）+ 唯一依赖 `@huggingface/transformers`（本地 embedding 必需，纯 JS + 预编译 ONNX 运行时）。
- 前端：原生 HTML/CSS/JS（ES Modules），无框架、无打包。
- 启动：`start.bat` → `node server/index.js` → 自动打开 `http://localhost:8770`。

## 2. DeepSeek 缓存适配（核心差异化设计）

### 2.1 官方机制要点（2026-08 官方文档核实）
- 命中条件：**从第 0 个 token 开始的完整前缀匹配**，中间改动即断裂；64 tokens 起存；有效期"几小时到几天"；尽力而为不保证 100%。
- 计费：`deepseek-v4-flash` 输入命中 **0.02 元/M**、未命中 **1 元/M**、输出 **2 元/M**；`deepseek-v4-pro` 为 0.025 / 3 / 6 元/M。峰谷时段（北京时间 9-12、14-18）价格 ×2。
- 响应 `usage.prompt_cache_hit_tokens / prompt_cache_miss_tokens`（流式需 `stream_options.include_usage`）。
- 每项目固定传 `user_id` 实现 KVCache 隔离。

### 2.2 "历史堆 + 尾追加"请求组织模型（本书核心机制）

每个作品维护一条**不可变的历史消息数组**（History Stack）：

```
history = [
  { role: 'system',  content: 书级系统提示（一次定稿，永不修改） },
  { role: 'user',    content: 公共材料（世界观/人物卡/书级大纲，永不修改） },
  { role: 'assistant', content: 第1章·场景1 正文 },
  { role: 'assistant', content: 第1章·场景2 正文 },
  ...（按写作顺序追加，只增不改）
]
```

写作第 N 章时：
1. **章规划请求**：`[...history, user(规划指令)]` → 章节细纲（JSON）。**细纲不进 history**。
2. **逐场景正文请求**：对每个场景 k：
   - `[...history, user(正文指令_k)]` → 场景正文，生成后 **push 进 history**。
   - 正文指令_k 携带：本章细纲、激活的世界书条目、向量检索的相关事实/伏笔、覆盖校验要求。
3. **章审校请求**：`[...history, user(审校指令)]` → 问题清单（JSON）。
4. **章结算请求**：`[...history, user(结算指令)]` → 抽取事实/角色状态/伏笔动作（JSON），落事实库；**不进 history**。

**缓存收益分析**：
- 第 N 章第 k 个请求的命中前缀 = "公共材料 + 第 1 章…第 N-1 章 + 第 N 章已写场景"——即全书历史，逐请求递增复用；
- 未命中部分仅 = 本条指令（数百 tokens）+ 本次输出，占比极小；
- 长篇小说（50 章 × 3000 字 ≈ 20 万 tokens 历史）下，理论命中率 > 95%，输入成本约为未命中方案的 1/50；
- 章内场景间前缀连续递增（场景 k+1 请求的前缀包含场景 k 的输出），场景间零额外成本。

### 2.3 缓存纪律（代码强制，UI 提示）
1. system 与公共材料**只允许在"作品设置"里编辑，保存时整体重写**（提示"修改公共材料将重建缓存"）；
2. 历史只允许尾部追加；修订场景文本时，仅允许"追加修订说明"或"替换当前章尾部段落"（UI 明确提示缓存重建代价）；
3. 所有动态内容（细纲、检索结果、指令）一律放最后一条 user 消息；
4. 每次请求上报 hit/miss token，成本面板实时显示命中率；命中率低于阈值（如 70%）时 UI 黄条提示原因（如"公共材料被修改"）；
5. 批量写作建议避开峰谷时段（9-12、14-18），成本面板按峰谷价测算。

### 2.4 上下文预算（V4：1M tokens）
- 历史按章估算 token（本地估算器：CJK ≈ 1.05 token/字，ASCII ≈ 0.3 token/字符，取整+安全系数）；
- 默认策略：**缓存优先**（完整携带历史，不压缩），当历史 > 阈值（默认 400K，可配）时提示两种降级：
  - A. 归档早期章节为摘要（重建缓存一次，之后继续递增）——适合超长篇；
  - B. 新开"续卷"（新 history，公共材料携带卷级精简版）——适合百万字连载；
- 阈值与策略在作品设置中配置，UI 显示进度条。

## 3. 分层写作管线（Plan → Write → Audit → Settle）

```
┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐
│ 世界观   │ → │ 书级大纲 │ → │ 卷大纲   │ → │ 章细纲   │ → │ 场景正文 │ → │ 审校/修订│
│ 人物/势力│   │ (梗概/主题)│   │ (卷目标) │   │ (要点/冲突)│   │ (逐段生成)│   │ (一致性) │
└─────────┘   └─────────┘   └─────────┘   └─────────┘   └─────────┘   └─────────┘
                                                                              ↓
                                                        ┌─────────┐   ┌─────────┐
                                                        │ 章结算   │ → │ 事实库/  │
                                                        │ (抽取)   │   │ 伏笔/摘要│
                                                        └─────────┘   └─────────┘
```

### 3.1 各阶段任务与模型路由

| 任务 | 模型（默认） | temperature | 输出格式 | 是否进 history |
|---|---|---|---|---|
| 世界观/设定生成 | flash | 0.8 | JSON/文本 | 否（公共材料） |
| 书级大纲 | flash | 0.7 | JSON | 否（公共材料） |
| 卷大纲 | flash | 0.7 | JSON | 否 |
| 章细纲 | flash | 0.7 | JSON（结构校验+重试） | 否 |
| 场景正文 | **pro** | 0.9 | 纯文本 | **是** |
| 一致性审校 | flash | 0.2 | JSON 问题清单 | 否 |
| 要点覆盖校验 | flash | 0.2 | JSON | 否 |
| 修订重写 | pro | 0.7 | 纯文本 | 替换/追加 |
| 章结算（抽取） | flash | 0.2 | JSON（schema 校验） | 否 |
| 摘要压缩 | flash | 0.4 | 文本 | 否 |

所有路由、温度、max_tokens 均在设置中可配（每任务独立覆盖）。

### 3.2 章细纲（Plan）
输入：本章编号、卷目标、最近 3 章摘要、活跃伏笔、待回收伏笔提醒、检索到的相关事实。
输出 JSON：
```json
{
  "title": "章节标题",
  "goal": "本章要达成的叙事目标",
  "conflict": "核心冲突",
  "scenes": [
    { "id": "s1", "pov": "视角角色", "location": "地点", "beat": "场景节拍/事件", "target_words": 1000 }
  ],
  "foreshadows_used": ["伏笔id"],
  "new_hooks": ["埋设的新伏笔描述"],
  "checkpoints": ["本章必须覆盖的细纲要点，供覆盖校验"]
}
```
细纲输出后**必须人工确认**（默认：自动确认开关可关）才进入正文阶段。

### 3.3 场景正文（Write）
正文指令模板（最后一条 user 消息）：
```
【本章细纲】{scenes[k] 及前后场景摘要}
【当前状态】{上场景末尾 2 句 + 角色状态快照}
【相关设定】{激活的世界书条目}
【相关事实】{向量检索 Top-K + 活跃事实}
【活跃伏笔】{需呼应/推进/回收的伏笔}
【写作要求】{文风/视角/人称/字数/去AI味规则/禁止事项}
```
要求：只写当前场景；不重复已写内容；结尾停在场景节拍完成处；事实必须与【相关事实】一致，不得编造新设定（新设定须写入"待登记"标记，结算阶段登记）。

### 3.4 一致性审校（Audit）
- 请求携带：本章全文 + 事实库相关条目 + 活跃伏笔表 + 角色状态；
- 输出 JSON 问题清单：`{type, severity, quote, issue, fix_suggestion}`；
  - type ∈ {角色矛盾, 时间线冲突, 设定冲突, 人称/视角, 伏笔遗忘, 事实编造, 语句质量, 大纲偏离};
- 处理策略：
  - 文本级（语句/错别字/重复）→ 本地规则优先（重复词、语病模式），必要时修订重写；
  - 事实级 → 写入事实库冲突记录，标记 superseded，后续章节自动采用新事实（不回改历史，连载式圆场）；
  - 严重且属于当前章 → 修订重写当前章尾部场景（UI 提示缓存重建代价，默认允许）；
  - 大纲偏离 → 要点覆盖校验失败，追加修订指令强制补写；
- 修订次数上限（默认 2 轮），超限转人工。

### 3.5 章结算（Settle）
抽取并落库（flash + JSON schema 校验）：
- 新增事实（原子事实，含来源章节、状态 active）；
- 角色状态变化（位置/实力/关系/持有物 delta）；
- 时间线事件；
- 伏笔动作（埋设/推进/回收 → 更新 ledger）；
- 本章摘要（150 字，供后续检索与上下文压缩）；
- 待登记新设定（正文中出现的未登记名词，提示用户确认后入世界书）。

## 4. 记忆体系（MemGPT 式三层 + 事实库 + 向量库）

| 层 | 内容 | 存储 | 注入方式 |
|---|---|---|---|
| 核心记忆 | 世界观、人物卡、势力、地点、物品、书级大纲 | SQLite + 世界书 | 公共材料（前缀，恒定） |
| 工作记忆 | 当前章细纲、上场景尾句、角色状态快照 | SQLite（临时） | 正文指令（尾部，动态） |
| 档案记忆 | 已写章节全文、摘要、事实库 | SQLite + 向量库 | 历史堆（前缀）+ 检索注入（尾部） |

### 4.1 事实库（Factbook）——幻觉控制的锚
- 表：`characters / locations / items / factions / events / facts / foreshadows / timeline`
- `facts` 为原子事实：`{id, subject, predicate, object, source_chapter, status(active|superseded|contradicted), note}`；
- 写作指令注入"相关事实"时，只注入 active 事实；superseded 事实以"已修正：旧值→新值"形式注入，防止模型使用旧设定；
- 章结算抽取 vs 指令中已有事实：冲突时生成"冲突记录"，提示用户裁决或自动采用新事实。

### 4.2 世界书（Worldbook）——SillyTavern 模式
- 条目：`{id, keywords[], content, priority, enabled, category}`；
- 关键词子串匹配（中文不需要整词匹配），扫描对象：本章细纲 + 检索上下文；
- 按 priority 排序、token 预算上限（默认 2000，可配）裁剪；
- 类别：世界观/势力/地点/物品/人物细节/文风规则。

### 4.3 向量检索（本地 embedding）
- 模型：`bge-small-zh-v1.5`（transformers.js / ONNX，量化版 ~100MB，HuggingFace 下载后缓存本地）；
- 索引内容：章节文本分块（512 字滑窗）+ 事实条目 + 章节摘要 + 伏笔描述；
- 查询时机：章细纲（检索相关历史剧情）、场景正文（检索相关事实/前文细节）、审校（检索矛盾候选）；
- Top-K 默认 6，注入正文指令【相关事实】段；
- embedding 初始化失败（无网/模型损坏）时**优雅降级**：仅用关键词检索（事实库 subject/predicate 匹配），功能不中断；
- 首次运行下载进度在 UI 显示。

## 5. 伏笔管理（Foreshadow Ledger）

```json
{
  "id": "fs-0007",
  "desc": "苏晚随身玉佩在月圆夜微微发烫",
  "type": "物品伏笔|身份伏笔|剧情伏笔|对话伏笔",
  "planted_chapter": 5,
  "advance_chapters": [8, 12],
  "payoff_chapter": 25,
  "status": "planted|advanced|paid_off|abandoned",
  "importance": "high|medium|low",
  "note": ""
}
```
- 埋设：章细纲的 `new_hooks` 自动登记；正文出现疑似伏笔（结算抽取）自动建议登记；
- 注入：正文指令【活跃伏笔】列出 status ∈ {planted, advanced} 且与本章相关的伏笔（按 importance 排序，预算内）；
- 回收：细纲中显式声明 payoff 场景，写作指令强制要求"回收必须让读者可回忆"（简述伏笔由来）；
- 审计：审校阶段检查——超过 `payoff_chapter + 容忍章数`（默认 10 章）未推进/回收的伏笔 → 生成"伏笔遗忘预警"卡片；
- 看板：UI 中伏笔状态看板，按章筛选。

## 6. 幻觉控制矩阵

| 幻觉来源 | 控制手段 |
|---|---|
| 模型凭空编造设定 | 正文指令硬约束"新设定必须来自【相关设定】"；结算抽取未登记名词 → 待确认队列 |
| 使用过期设定 | 事实库 superseded 机制，注入新旧值对照 |
| 时间/地点/在场角色错乱 | 角色状态快照 + 时间线注入；审校专门检查 |
| 前后文重复/自相矛盾 | 向量检索注入相关前文 + 审校对照 |
| 输出格式不稳定 | JSON schema 校验 + 自动重试（最多 2 次，失败转人工） |
| 长上下文中间遗忘 | 分场景写（每场景 ≤1200 字）；工作记忆精炼注入 |

## 7. 成本控制全景

1. **缓存命中**：见 §2，历史堆机制使命中率 >90%，输入成本降为 1/50；
2. **任务路由**：正文外全部走 flash（3~6 倍价差）；
3. **本地检索**：embedding/向量检索零 API 成本；
4. **摘要压缩**：超长时早期章节摘要化（可选，默认关）；
5. **输出节制**：场景 target_words 900-1200，防止无效冗长；
6. **峰谷错峰**：9-12、14-18 价格 ×2，成本面板提示批量写作建议时段；
7. **成本面板**：每请求记录 {task, model, prompt_hit, prompt_miss, completion, 实际费用, 若未命中的费用, 节省比}；按任务/章节聚合；累计"已节省"金额。

## 8. 数据模型（SQLite，node:sqlite）

```sql
books(id, title, genre, created_at, updated_at, settings_json)   -- settings_json: 模型路由/温度/预算/策略
public_materials(id, book_id, kind, content, version)            -- system/世界观/人物卡/书纲；version 用于缓存重建提示
volumes(id, book_id, idx, title, goal, outline_json, status)
chapters(id, book_id, volume_id, idx, title, outline_json, status, word_count, created_at)
   -- status: planned|outlined|writing|drafted|revised|settled|done
scenes(id, chapter_id, idx, pov, location, beat, content, target_words, status)
history(id, book_id, seq, role, content)                         -- 历史堆（append-only；role=system/user/assistant）
facts(id, book_id, subject, predicate, object, source_chapter, status, note)
characters(id, book_id, name, card_json, state_json, first_chapter, last_chapter)
locations/items/factions(同 characters 模式)
foreshadows(id, book_id, desc, type, planted_chapter, advance_chapters, payoff_chapter, status, importance, note)
worldbook(id, book_id, keywords, content, priority, category, enabled)
chapter_summaries(chapter_id, summary, updated_at)
conflicts(id, book_id, chapter_id, type, quote, issue, resolution)
usage_logs(id, ts, book_id, task, model, prompt_hit, prompt_miss, completion, cost, cost_if_miss, extra)
vectors(id, book_id, kind, ref_id, chunk, embedding_json, created_at)
settings(key, value)                                            -- 全局设置（API key、默认路由）
```

### 8.1 备份
- `GET /api/backup` → 导出 `novel_backup_YYYYMMDD_HHmmss.zip`（SQLite 文件 + data/models 索引清单）；
- 数据目录：`data/{book_id}/` 下 JSON 镜像（正文纯文本便于用户直接读取/复制），SQLite 为权威。

## 9. API 设计（REST + SSE）

```
GET  /api/health
GET  /api/settings  PUT /api/settings           -- API key 只写不回显
POST /api/books  GET/PATCH/DELETE /api/books/:id
GET  /api/books/:id/public-materials  PUT /api/books/:id/public-materials  -- 整体重写，提示缓存重建
POST /api/books/:id/outline/generate            -- 书级大纲（生成向导）
POST /api/books/:id/volumes/:vid/generate       -- 卷大纲
POST /api/books/:id/chapters/:cid/outline       -- 章细纲（SSE 进度）
POST /api/books/:id/chapters/:cid/write         -- 写正文（SSE：场景进度+流式文本）
POST /api/books/:id/chapters/:cid/audit         -- 一致性审校（SSE）

POST /api/books/:id/chapters/:cid/coverage      -- 细纲要点覆盖校验
GET  /api/books/:id/foreshadows  POST ...        -- 伏笔 CRUD + 预警

```
SSE 事件：`{type: 'progress'|'delta'|'usage'|'done'|'error', ...}`——`usage` 事件实时上报 hit/miss，前端成本面板即时更新。

## 13. 风险与对策

| 风险 | 对策 |
|---|---|
| API Key 泄露 | 只存本地 config.json（0600）；UI 不回显；无任何遥测 |
| 缓存不生效 | hit 监控 + 命中率告警；文档说明前缀纪律；公共材料编辑时明确提示 |
| embedding 模型下载失败 | 优雅降级到关键词检索；UI 显示下载进度与重试 |
| 模型输出 JSON 不稳 | schema 校验 + 重试 + 转人工 |
| 超长篇上下文超限 | 阈值预警 + 摘要归档/续卷两种降级 |
| 峰谷价格翻倍 | 成本面板提示 + 批量任务排程建议 |
