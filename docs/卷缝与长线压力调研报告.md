# 卷缝、台账老化与长线压力（V0.102）

> 日期：2026-08-30｜依据：正式库《示例历史长篇》第 1—34 章台账、书纲实际对齐段、V0.101 写时配额之后仍未覆盖的中长线缺口
> 目的：让自动创作在**卷边界**和**章规划**上同时看见短线承接、中线卷责、长线债务，而不是把 90 条钩子和 42 条无回收章伏笔整表灌进下一章指令。

## 结论先行

存量 34 章已经写完四卷，但中长线合同是空的：

| 观察 | 数字 | 后果 |
|---|---|---|
| 卷体检 | 0 条记录 | 卷与卷之间没有“上一卷实际交了什么”的编译结果 |
| 快感钩 | 91 条，只兑 1 条 | `settleHookLedger` 只老化 long/super，short/medium 永开；写作指令被过期账本淹没后模型选择忽略 |
| 伏笔 | 44 条，几乎全是 planted 且无 payoff_chapter | `forgotten()` 要求 payoff_chapter 非空，无回收章的坑永远不会超期 |
| 故事弧 | 配角丙/贾似道停在 17，配角甲弧 last_active=8（人却写到 33） | 卷纲看不到停滞弧，下一卷继续只推进“看图辨迹”微能力循环 |
| 卷 4 承诺 vs 正文 | 卷纲写“就任东崖防区指挥”，第 34 章实际是北崖值夜、蒙哥入蜀 | 懒加载卷 5 时若只读书纲分卷句，会从幻想交接起笔 |

短线（单章文笔）V0.101 已补配额/语音/低谷。本轮不改已有正文，把缺口收成**卷缝编译器**：上一卷实际出口 + 有界兑付队列 + 停滞弧必须动 + 禁止把上一卷的观察-记录骨架再写一卷。

明确不做：不把 90 条钩子一次性兑完、不引入多 Agent、不在本轮改《实测》已发布 1—22 章正文。

## 框架动作

1. 纪律：卷纲/章纲只注入编译后的【卷缝】【本章长线简报】，禁止整表。
2. 槽位：`horizon.js` 纯函数产出文本，只进 L4。
3. 校验：卷纲落库前 `validateVolumeSeam` 与生命周期校验并列；首章必须咬住实际出口事实。
4. 台账：short/medium 超期无推进则 expire，不转伏笔；无回收章的旧伏笔进入本卷有界队列。
5. 测试：`tests/v1020.test.js`；非该题材零影响（无前卷时缝为空、校验通过）。
