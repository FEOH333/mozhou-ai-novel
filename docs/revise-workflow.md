# 章节人工精修工作流（例外通道 · L2 Writer Review）

> **定位声明（必须先读）**：按《墨舟开发宪章》§4，本项目 AI 的**本位是编程 AI——第一选择永远是完善自动创作工具**（纪律文本 → 本地防线 → 审校指令），让管线自己拦下、抓出、修好；**直接人工修改原文是例外通道，仅限"存量稿已错且工具无法自愈，且用户明确要求精修"**。本文件是这条例外通道的唯一权威协议，同时强制要求：**精修中发现的任何可工具化缺陷必须回写工具**（宪章 §4/§10.1），防止再犯。
>
> 本文件面向 **dsh 作家子代理**（`subagent_with_model` / `subagent_fork_with_model`）执行"诊断 → 精修 → 验收"。调用者（主 agent）不要转述本协议，应让子代理**自己读取本文件与下方引用的纪律文本**后再执行，保证零信息损耗。

---

## 1. 触发条件核对（不满足则拒绝进入精修）

进入本流程前，调用者必须逐条核对（缺一项即转回工具通道）：

- [ ] 存量章节已写坏（已落库），且**工具无法自愈**（管线自愈/最小修订跑过或明确不适用）；
- [ ] **用户在本会话明确要求人工精修**（不允许子代理自行决定代笔）；
- [ ] 已确认不涉及已完成章节的"计划反压正文"问题（宪章 §6.1「完成章以实际正文为权威」）；
- [ ] 应用修改的写回路径已确定（见 §10），不做未经确认的直写。

若用户实际诉求是"审读产出章节并让工具变好"→ 改走宪章 §10.1 文学审读模式（审读即落地到工具），不进入本流程。

## 3. 作家 persona（子代理系统提示）

```
你是一位资深中文出版编辑，专精长篇历史网文，二十年编辑经验，第一原则是"作者的声音高于一切"。
按任务切换三重身份：主编（诊断：冷静克制，意见必须具体到句子并给出改法）、
作家（精修：手上功夫好但不炫技，目标是让读者觉得"作者进步了"而非"换了个写手"）、
验收编辑（只关心"这章现在能不能发"，明确给"通过/改后再看"）。

你的行业标准：
- 可读性优先：看得懂永远比显得高级重要；一段话里读者只需要呼吸一次。
- 克制即力量：能删则删；形容词是负债；准确比华丽贵十倍。
- 人物优先于情节：对话里每个人都该有自己的声音，人物反应必须符合其动机与人设。
- 文风一致性：动笔前先在心里建立本文的文风指纹（句式习惯/词汇偏好/节奏特征），任何修改不得破坏它。
- 证据纪律：你的每一条意见必须有可回指正文的逐字引文（宪章 §6.5）；引文不存在=意见作废；不编造"偏移量/改法"当事实。
- 历史题材底线：时代质感要真（器物/礼制/称谓/价值观），但语言是现代汉语；考据不确定就标〔存疑〕，绝不编造。
```

## 5. 阶段一 · 主编诊断协议

**判据即项目的纪律真源**（§4），不是通用文学术语——每条问题必须能指回一条具体纪律/词表/红线，说不出判那就是主观低优先级意见（归 `tradeoffs`，不驱动精修）。

每条意见固定三件套：
1. **定位**：段落位置 + **逐字原文摘录**（引文必须能在正文中不差分毫找到；找不到则该意见作废，不进入修改链）；
2. **判据**：违反哪条纪律/词表/量化红线（如"redlines.js 破折号类：本章 22 处 > 20"、"WARFARE_BLOOD_TEXT：战斗章无一处白刃现场"）；
3. **改法正例**：一句可执行的"改成什么样"（禁令必须结对正例，宪章铁律 1）。

分级：`高`（必须改）/`中`（建议）/`低`（可不改）。另给独立的 `tradeoffs` 区（读者偏好取舍，不冒充问题）。
**结束语必须回答**：本章"可精修"（文字层可救）还是"建议返工"（情节/结构层该重写）？后者只给返工建议要点，不进入精修。

覆盖维度（每条都回到纪律真源）：结构推进、人物动机与对话个性、节奏分配、语言精炼度与 AI 味词族、与前情/大纲的一致性、历史质感与考据、读者体验（兴奋点/跳读区）。

---

## 6. 阶段二 · 作家精修协议

1. 先读原文建立文风指纹，再对照工作单逐项动笔；**未列在清单上的问题不扩权**（错别字/标点除外，且改动说明里注明）。
2. 动笔纪律：
   - 改句子不换文风；**最小改动优先**（能改三分不动五分）；
   - 删减优先于堆砌；对话贴近人物，避免同声；
   - 增写内容（过渡/动作/心理）必须风格无缝融合，并在**改动说明**中标注 `〔增〕`；
   - **标注只进改动说明，禁止写入正文文本**（V0.98.14 实证：`〔存疑：…〕` 注记段被写进 ch26 正文触发元话语铁律、`〔存疑〕` 句内插标写进 ch24——正文对读者说话即破功；存疑事项写进改动说明与交付注记即可）；
   - **引文重定位**：任何引用原文的操作，改后必须可与原文/差异包对得上，禁止凭空新增人物事件（宪章 §6.5）。
3. 一次完成全章，中途不自评。

### 反 AI 腔红线（升级为"禁令 → 正例 → 量化"，与 redlines.js 同源）

| 禁令 | 正例 |
|---|---|
| 不禁/仿佛/宛如/若有所思/良久/缓缓（软词滥用）| "他握着茶盏，指节泛白"（不用"仿佛很紧张"）|
| 禁"嘴角勾起一抹弧度/命运的齿轮/某种说不出的"等套话 | "他笑了，眼里没有笑意" |
| 禁对称排比与三连句成串 | 打断排比，长短句交错 |
| 禁每段末尾总结升华 | 让动作/画面收尾，不替读者下结论 |
| 禁书面腔写对话 | 对话用耳朵写："嗯。""走。" |
| 禁喻体堆砌（金句密度过高）| 一章至多两三处亮喻，其余留给事实 |
| 禁"然而/但是"转折串糖葫芦 | 合并转折，一句到位 |
| 禁大词拔高日常（气氛组形容词）| 具体细节替代："殿柱三人合抱，琉璃瓦泛青光" |

量化边界以 `server/data/redlines.js` 为准（词表、段落长度、同词复读、起手式/收束词族——写审同源，精修同样遵守，不得制造新的检测命中）。

## 7. 历史题材专项条款

- 时代质感优先于辞藻：宁可平实准确，不要伪文言；现代读者读得顺第一。
- 称谓一致：同一人物在同一叙层级称谓固定（名/字/号/官职按场合切换，不混用）。
- 考据纪律：不确定的器物/礼制/生卒/事件 → 查证或标〔存疑〕，禁止编造（`server/data/history.js` 有史实锚点可查）。
- 调性参照本项目《历史磅礴感与山河尺度调研报告》及其落库纪律：需要"山河尺度"的段落允许拉远镜头与景深（分层视角配额），日常叙事不人为拔高。
- 战争/朝堂段落同时受 `WARFARE_BLOOD_TEXT`/`COURT_INTRIGUE_TEXT` 约束（白刃现场、人物博弈），精修不得把它改"安全"。

## 8. 阶段三 · 验收协议

通读修改稿检查：视角是否漂移、人名地名时态一致、AI 味词族是否清零（对照 redlines.js）、与文风基准贴合度、增写段落是否证明必要。输出 `通过` 或 `改后再看`（附必须处理的最后清单）。

---

## 9. 交付与落库（禁止直写）

**输出结构**（阶段二）：
```
## 改动说明
| # | 定位/原文引 | 类型（删/改/增/调序）| 级别 | 判据（纪律）| 理由（一句话）|
## 修改后全文（完整，从标题到文末，不可省略）
```

**写回路径（按宪章 §2 铁律 3、§4、§6.1）**：
- 绝不直写数据库、绝不绕过 `writeScene → reviseScene → validateChapterRewrite → applyValidatedChapterRewrite`（场景级 `applyValidatedSceneRewrite`）；
- 存量稿例外修复走**幂等维护脚本**（`server/maintenance/` 模式：默认 dry-run、显式 `--apply`、备份+快照+事务+复验，参照 `repair-*.js`/`patch-chain.js` 锚点补丁幂等三分法）；
- 已完成章节的修改，先与用户确认并给出**线上同步差异清单**（段落级 diff），应用后复验正文哈希与（若涉及）`history_seq` 换版，防止旧稿随缓存上下文复活；
- 若运用项目现有 `reviseScene` 时，注意其 `resetFollowing=true` 语义——存量精修必须显式传 `false`（宪章 §6.9 存量维护红线①）。

## 10. 教训回写（本流程存在的意义）

精修中发现的**可工具化缺陷**必须逐条产出"工具改造建议"，落到宪章框架扩展范式（§5 五件套）而非硬编码特判：

- 新 AI 味词/新章法复读/新起手式收束 → 提 `server/data/redlines.js` 词族 + 纪律文本（写审同源，注入必可检）；
- 新量化红线（段落长/复读窗/阈值）→ 单一真源进 redlines.js，指令与审校共用；
- 系统性文风漂移 → 纪律文本 + 三层防线（单章/三章一轮/漂移信号）；
- 具体章节/书名的教训 → 收敛为题材/框架配置，**禁止用书名当开关**（宪章铁律 2）。

交付物 = 修改稿 + 改动说明 + **工具改造建议清单**（交给主 agent 决定是否落地，落地走 RED→GREEN 测试）。
