## 2. 关键机制提炼（按主题）

### 2.1 记忆体系（NovelClaw —— 最重要）
- **固定注入 + 检索混合**：`get_relevant_context` 先把「滚动摘要 1 条 + 最近 2 章摘要 + 最近 6 条事实卡 + 各核心 bank 最新 1 条」固定塞进上下文（保证召回），向量检索 top_k=10 只作补充。**不要只靠向量检索**。
- 16 个记忆银行分 6 类：outlines（global/chapter/rolling_summary/chapter_summary/turning_point）、characters、world_settings、plot_points、fact_cards（general/world_rule/continuity）、texts。
- 记忆评分：语义 0.5 + 重要性 0.25 + 新近度 0.15（14 天半衰期）+ 强化 0.10（封顶 12 次）+ 主角锚点加分 0.18（衰减 0.35/章）。
- 每章 finalize 后状态写回：标题、章节大纲、摘要、**滚动摘要增量更新**、事实卡、一致性问题（revision_notes 供续写参考）。
- 注入位置：system prompt 之后第一条就注入记忆，优先级高于 RAG。

### 2.2 章节任务单合同化（AI-Novel-Writing-Assistant）
章节任务单 = 章节目标 + **承接上一章** + **铺向下一章** + 场景卡 + 出场角色 + **必须兑现/铺垫（伏笔账本）** + **禁忌硬约束**。写作 prompt 只带任务单 + 目标字数，避免膨胀。
书契约（book_contract）= 目标读者 / 卖点 / **前 N 章承诺** / 硬约束，作为整本书顶层合同，经约束引擎转成后续每章约束摘要。
**质量债务 8 档**：accepted / continue_with_warning / local_patch_plan / patchable_obligation_gap / draft_obligation_unmet / defer_and_continue / replan_required / stop_for_replan——局部问题**记债继续，不阻断全局**。
状态回灌闭环：角色状态 / 事实账本 / 伏笔账本（payoff ledger：铺垫、兑现、延期、风险）/ 世界状态 / 审核问题，每章回灌。

### 2.3 伏笔（show-me-the-story + NovelClaw）
- 数据结构：`Foreshadow{ID, Name, Description, PlantChapter, TargetChapter, Status, Events[{Chapter, Note}], Resolution}`——**Events 每章推进流水**可追溯。
- 注入规则：只注入活跃伏笔；**距回收章 ≤2 章提示"可开始收束"；超期（>target+3）注入"本章应优先回收"警告**。
- 追踪 prompt：只返回有变化的条目，区分"推进"与"真正回收"（谜底完全揭开才算 resolved）。
- 大纲一致性检查：每条伏笔在大纲中是否有埋设/回收空间，输出 suggested_fix: revise_outline|adjust_foreshadow|abandon。
- 转折点追踪（NovelClaw）：检测 4 类转折（伏笔/人物变化/情节转折/关键事件），实时编辑器检查"转折是否突兀、是否缺铺垫"。

### 2.4 Fact-check 与审校边界（show-me-the-story）
- **严格限定核查范围**：仅 6 类客观矛盾（姓名不一致、时间线倒错、与前情矛盾、能力身份与设定冲突、提前引入后续章节安排、一次性事件重复）；**主观问题一律 PASS，拿不准一律 PASS**——压制误报。
- 重试 ≤3 次；失败 issues 去重累积，重试带累计失败项。
- 3 次仍失败 → 根因分析（foreshadow_outline/outline_history/foreshadow_history/mixed）→ 可调和则生成 extra_constraints 注入再试；不可调和挂起，给用户 4 选项。
- **写前防线**：动笔前先做大纲一致性检查（本章大纲 vs 前情 + 上一章结尾），冲突则先修订大纲再写。
- 修订后**级联**：重摘要 → 联动修订后续未确认章节大纲 → 重同步伏笔/记忆（旧记忆先删再重提取）。

### 2.5 长度硬约束与自愈（NovelClaw）
- 每章硬性目标字 [min, max]，prompt 明示"必须输出 X–Y 字"。
- 超上限 → 整章重写压缩（保留剧情删冗余）；不足下限 → **续写子轮**（≤3 轮，要求承接已写内容、不重写开头、不重复段落）。
- 软截断在句号/感叹号处，绝不拦腰切断。
- 章节软目标 3300-3700 字，章数 = target/3500 夹在 [4,80]。

### 2.6 全书 polish 工单化（show-me-the-story）
1. 诊断：通读设定+摘要+全文 → 结构化报告（总评/结构节奏/人设台词/设定硬伤/文风 AI 味/优先修改 P0/P1/P2，每条定位章节）。
2. 一致性核查：5 维（时间线/人设/地理道具/伏笔/章间衔接）Markdown 表格（严重度/章节/原文摘录≤30字/矛盾说明/最小改法）。
3. 工单生成：`{chapter_num, type(logic/transition/style/rhythm/dialogue/polish), priority, feedback(50-150字), selected}`，**同章问题合并一条**。
4. 执行：逐章最小化修订，记录前后 500 字 diff，无变化标 skipped；可中断续跑。
5. 可选 SmoothTransitions：逐章比对上一章结尾 vs 本章开头，生硬才重写开头片段。

### 2.7 网文套路量化指标（novel-writing-framework —— AI 本位核心资产）
**AI 本位 = 把套路内建为硬规则**，用户不需要懂：

- **写前阻断五问**（每章动笔前 AI 自检，不过不写）：
  1. 反派造成什么可见伤害？（谁受伤/什么被破坏）
  2. 物理对抗是什么？（手碰金属/火焰/拳头——纯对话不算）
  3. 爽点能用"主语+动词+宾语+对方损失"描述吗？
  4. 结尾最后一句话让读者心跳加速吗？（"下一页！"不是"温暖"）
  5. 前 300 字有没有物理事件？（炸了/断了/打了/冲了/倒了/烧了）
- **番茄 3 秒原则**：前 300 字必须出事；3-5-10 爽点法则（3 章小爽/5 章大爽/10 章高潮）；结尾只写四种（危机突降/悬念反转/挑衅叫板/死亡倒计时）；爽点七种（打脸/碾压/装逼/截胡/复仇/升级/反转）轮换。
- **13 项量化指标**：CJK≥2000/章（红线 1500）；"不是X是Y"≤2/章；元话语 0 次（"卷一/第X章/前文/后文/本章"）；破折号≤20/章；段落≤200 字（听书≤100）；战斗章感叹号≥2；同场景≤3 章；长线钩子间隔≥2 章。
- **AI 口水词黑名单**：缓缓、不由得、眼底闪过、心中升起、说不出的、这意味着、他的眼神、她的眼眸、深邃、不可置信。
- **"不是X，是Y"改造**：直接写 B；X/Y 是具体可感知名词保留，抽象概念/情绪必改。
- **"他感到"改造三法**：直接呈现（删掉，让神经/肌肉做主语）/ 动词替代 / 因果链。
- **起点铁律**：每 10-15 章必须有人死（名字提前让读者熟悉）；主角每 10 章至少 1 次亲手战斗；钩子五类轮换；反派必须能说话有逻辑；每 3 章 AI 指纹扫描（后期修复成本是初稿 10 倍）。

### 2.8 AI 指纹黑名单（tianming-skill —— 7 类一票否决）
1. 套路化连接词：然而/与此同时/不仅…而且…/众所周知/值得一提的是/综上所述
2. 万能形容词：无与伦比/美轮美奂/叹为观止/举世瞩目/淋漓尽致
3. 客观陈述腔：需要注意的是/不难看出/显而易见
4. 凑字副词：非常/十分/相当/极其/特别
5. 比喻陈词滥调："像…一样/似的"+眼睛像星星/笑容像阳光/心情像过山车
6. 无逻辑递进的三段式排比
7. 恐怖/紧张场景中的大段心理独白
净化重构最多 3 次，失败交人裁决。

### 2.9 渲染指令四则（tianming-skill）
1. **感官优先于思考**：恐惧场景 70% 笔墨写生理感官，禁长心理独白
2. **动作切断语言**："心跳擂鼓。他猛地撑桌，起身。"
3. **延长瞬间**：子弹时间拉长到数百字
4. 非线性叙事

### 2.10 上下文组织（show-me-the-story 的章节写作注入顺序）
1. 核心写作提示 + 梗概
2. **前情提要**：最近 5 章摘要（结构化：核心/人物动态/心理轨迹/状态变化/关键细节/情绪色调）
3. **上一章结尾原文** ≤800 字（仅用于无缝承接）
4. 活跃伏笔块
5. **叙事记忆**：跨章长期细节（口头禅/承诺/道具），带原文位置引用
6. **全书章节脉络（反向约束）**：前文已发生事件列表（防重复）+ **未来 10 章大纲列表（防提前登场/剧透）**
7. 本章大纲、风格/视角、角色上下文（按大纲名字匹配注入）
8. 字数硬约束 + 生成后校验

### 2.11 skill 机制（ai-novelist）
- `data/skills/<name>/SKILL.md`：frontmatter（name+description）+ 正文
- system 只列全部 skill 一行摘要，**正文按需加载**（AI 判断任务匹配时调用）
- 写作风格技能包可复用此机制

## 3. V0.15 升级方案（AI 本位）

### 定位转变
v0.1 是"人工干预的写作管线"（细纲要确认、审校要裁决、场景要手动点）。
**V0.15 是"AI 全自动成书"**：用户给一句话灵感 + 选平台 → AI 自动完成 契约→设定→书纲→卷纲→逐章（细纲→正文→自审→自修→结算）→全书打磨。人工干预全部改为可选（专家模式）。

### 升级清单（全部标注借鉴来源）

**A. AI 本位自动管线（pilot）**
1. 一键全书模式 `/api/books/:id/pilot`：从当前进度自动写到指定章数/全书完成；每章结束 checkpoint，中断可续跑
2. 默认自动确认：细纲自动确认、审校自动修订、冲突自动记债（defer）
3. 新手向导：题材模板 + 一句话灵感 → 自动生成书契约 + 设定 + 书纲

**B. 章节任务单合同化**（AI-Novel-Writing-Assistant）
细纲增加：承接上一章 / 铺向下一章 / 必须兑现（伏笔账本）/ 禁忌硬约束；书契约（目标读者/卖点/前 N 章承诺）注入公共材料

**C. 记忆混合注入**（NovelClaw + show-me-the-story）
1. 滚动摘要（rolling summary）每章增量更新，写作指令固定注入
2. 固定注入区：滚动摘要 + 最近 2 章摘要 + 最近 6 条事实 + 角色状态
3. 反向约束：未来 3 章大纲（防剧透）+ 前文事件列表（防重复）

**D. 长度硬约束 + 自愈**（NovelClaw）
场景字数 [min,max] 硬约束；不足自动续写（≤2 轮）；超限自动压缩重写

**E. 网文套路内建**（novel-writing-framework + tianming-skill）
1. 平台模式：book.platform ∈ {番茄, 起点, 通用}；番茄注入 3 秒原则/结尾四钩子/爽点轮换，起点注入信息增量/死亡节奏/钩子五类
2. 写前五问自检：细纲生成后 AI 自检（可见伤害/物理对抗/爽点可描述/结尾心跳/前300字有事件），不过则重生成细纲
3. 量化 AI 味指标本地检测：不是X是Y、口水词黑名单（扩充 20+）、元话语 0 容忍、破折号≤20/章、段落>200 字、情感标签化
4. 渲染指令四则注入写作要求

**F. 伏笔升级**（show-me-the-story）
伏笔加 Events 流水；临近回收（≤2 章）与超期（>target+3）注入告警；细纲生成时校验伏笔-大纲一致性

**G. 质量债务多档**（AI-Novel-Writing-Assistant + show-me-the-story）
审校 verdict：accept / fix(自动修订) / defer(记债继续) / replan(重生成细纲)；pilot 模式永不 stop，问题全部记债 + 注入下一章圆场提示

**H. 全书打磨 polish**（show-me-the-story）
诊断（P0/P1/P2 定位章节）→ 五维一致性核查 → 工单合并 → 逐章最小化修订（记录 diff，可中断续跑）

**I. 专家模式**：设置开关，默认关闭（AI 本位）；打开后恢复人工确认/裁决 UI

### 不做（明确取舍）
- 不引入多 agent 自主循环（Claw ReAct）——成本高、不可控，我们的"确定性管线 + 质量债务"更适合 AI 本位批量生产
- 不引入 HITL diff 审批为默认流程（违背 AI 本位）——保留专家模式入口
- 不引入 MCP/function calling 壳——本工具是创作引擎不是 agent 壳
