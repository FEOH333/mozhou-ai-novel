# DeepWrite（v1.2.1）调研报告：特性对照与整合决策

> 调研对象：https://github.com/swjybky/deepwrite （v1.2.1，2026-08-08 发布）
> 调研目的：对照墨舟（V0.96.3）现状，识别可升级整合、提质提效的可取之处。
> 结论先行：**落地 1 项（快照 diff 对比视图，V0.96.4）；列入机会清单 1 项（学习仿写/风格特征提取）；其余对照项墨舟已具备或不适合整合。**

## 一、DeepWrite 是什么

本地写作 **Harness Agent 工作台**（Electron 桌面应用，pnpm monorepo）：把模型、提示词、写作技能、素材、文稿和工具组织在同一应用中，AI 理解当前作品、调用能力、修改真实文稿，**每次变更先出 diff 交用户审阅**。界面参考 Codex：左资源树 / 中智能体对话 / 右内容编辑。

## 二、特性对照（DeepWrite → 墨舟现状）

| # | DeepWrite 特性 | 墨舟现状 | 判定 |
|---|---|---|---|
| 1 | Codex 三栏工作台（资源树/对话/编辑器） | Web 工作台 + 全自动管线（AI 本位） | 不整合。交互范式不同：DeepWrite 是人机对话协作，墨舟是管线自动创作，照搬三栏反而削弱自动化定位 |
| 2 | 专业智能体分工（人物/剧情/大纲/正文专家/分节写手，各自系统提示词） | 管线天然分工：idea/outline/write/audit/revise/polish/signing 等 30+ 任务，各任务独立提示词与路由 | 已具备且更细（全自动管线 vs 手动逐环对话） |
| 3 | 每智能体独立配模型 + 默认思考等级 + 对话时按任务切换 | `DEFAULT_ROUTES` 按任务配 model/temperature/maxTokens/thinking/reasoningEffort；全局 routes 覆盖 + 作品级 routes 覆盖 + writingModel 档位 + 假定制迁移；设置页完整路由表格（模型下拉/自由输入 + 四参数） | **已具备**（原本疑似的"固定模型"不成立——三层合并早就在） |
| 4 | **可审阅的文稿修改**：写入先生成 diff，接受/拒绝后才落盘；并发更新保留较新版本防静默覆盖 | 快照体系完备（重写/打磨前自动快照 + 手动快照 + 回滚前自动备份），正文替换有 validate/apply 闸门；**但用户看不到"改了什么"**——回滚是全有全无，无差异可视化 | **落地（V0.96.4）**：快照 diff 对比视图。自动管线按 AI 本位照常自动应用（不引入人工卡点），diff 作为事后审阅入口补"可见性"缺口 |
| 5 | 本地优先（deepwrite.json + UTF-8 Markdown，Git 友好） | 本地 SQLite + config.json，数据零上云 | 已具备（等价；SQLite 换 Markdown 无收益） |
| 6 | 多协议模型接入（OpenAI Completions/Responses、Anthropic Messages、Google） | 多协议客户端（chat/responses/messages + 协议探测与锁定），服务商预设一键切换 | 已具备 |
| 7 | **学习仿写**：分阶段分析参考文本，提取可复用写作特征，用于后续创作（模型与提示词可单独配） | 风格画像+内置自撰样本+用户样本覆盖（反 AI 味），但无"从参考文本自动提取特征"能力；宪章 §12.2 已挂"风格克隆自动化——高成本" | **列入 §12.2 机会清单**。DeepWrite 证明存在低成本中间形态：分阶段提取（词频/句式/意象/节奏）→ 生成结构化风格特征卡 → 注入写作指令，不必做全量克隆 |
| 8 | 智能体回合网络波动自动重试 | resilience.js：智能重试（429/5xx/网络/卡死）+ 熔断 + 空转自动降档重试 | 已具备 |
| 9 | 云备份 | 本地优先定位 + 快照/回滚前自动 SQLite 备份 | 不整合（与本地优先定位冲突；用户可自行同步 data/） |
| 10 | 技能市场 / 外部技能导入 | 文学知识库单源治理（redlines.js 单一真源、纪律文本自撰、版权红线禁止照抄） | 不整合。外源提示词绕过"写审同源一把尺"与量化红线校验，与铁律 1/§6.1 单源信条直接冲突 |

## 三、落地决策

### 落地：快照 diff 对比视图（V0.96.4）

- **依据**：宪章 §6.8"后端能力必须有前端入口"——快照只增恢复、重写前自动快照等能力用户看不见改了什么；DeepWrite 的"可审阅修改"证明该入口是写作工具的标配信任机制。
- **范围**（最小高价值，不过度工程）：
  1. `server/util/diff.js`：段落级 LCS diff 纯函数（禁-增-同三类块）；
  2. `GET /api/books/:id/snapshots/:sid/diff`：无 `chapter` 参数返回差异章节概览（章号/标题变化/字数变化），带 `?chapter=idx` 返回该章段落级块 diff；
  3. 前端书务台快照卡片加「对比」入口：差异章列表 → 点开红删绿增块视图（连续未变段折叠）。
- **不做**：改自动管线的应用时机（AI 本位不新增人工卡点）；不做字符级 diff（段落级对修订审阅足够，成本高一个量级）。

### 机会清单：学习仿写（风格特征提取器）

写入宪章 §12.2：分阶段分析参考文本 → 结构化风格特征卡（词汇偏好/句长节奏/意象分布/对话密度/修辞频率）→ 并入 `creative_packs.js` 风格画像槽位 + 检测词表（注入必可检）。与 §12.2 既有"风格克隆自动化——高成本"项合并描述：DeepWrite 实证了低成本中间路径。

## 四、总体评价

DeepWrite 与墨舟是同一赛道的两种范式：**人机对话协作（人审每步）vs 自动创作管线（本地防线守质量）**。墨舟在任务分工、模型路由、韧性重试、本地优先上均已等价或更强；真正值得吸收的是它对**"用户对修改的可见性与控制感"**的执着——这正是墨舟"后端能力必须有前端入口"信条的具象化，落地为快照 diff 视图。云备份/技能市场与墨舟定位及单源治理信条相悖，明确不整合。
